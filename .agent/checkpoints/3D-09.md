### Design (decisions of this WP marked [A] until the owner confirms)
- Local frame boundary with 3D-32 [V: 3D-32 checkpoint, `src/crs/frame.js` on its branch]: `crs` maps file world
  coordinates to an origin-relative metric ENU frame (`toMetric` / `toWorld`); `brep/frame.js` adds only the
  `buildingAxisDeg` rotation about Z on top. `brep` takes the metric mapping as an injected argument and defaults to the
  projected-CRS path (`world - originWorld`, the same as 3D-32's projected branch), so `brep` does not import `crs`;
  3D-10 wires the two. No edit of 3D-32 files.
- Module DAG in `check:arch` includes `crs` as a leaf (`crs` <- `brep`, `import`, `export`) as 3D-32's accepted ADR
  amends C1 rule 2 (D-3D32-5 on its branch), so the merge of 3D-32 does not break the rule. Unknown `src/<dir>` fails.
- No-I/O rule scope: `packages/geo-model3d/src/**` (kernel code). Tests in `packages/geo-model3d/test/` read fixtures.
- Importers narrowed from `services/`, `tools/` to `services/kernel/` plus `tools/bench/` (the bench drives the kernel
  in-process by 3D-ADR-0006) [A].
- Lineage covers Face, HalfEdge, Vtx ids (topology-lineage description); op supplies `mapped`; transaction derives
  `deleted` and `preserved`. Model-level members (`state`, `frame`) are not patch entities (Q-31): reported beside the
  patch, not invented into it.
- `robust-predicates` (3D-ADR-0004 decision 3): brep has no orientation predicate; not adopted in 3D-09, left to 3D-12.
