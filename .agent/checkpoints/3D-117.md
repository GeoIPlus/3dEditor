# 3D-117 checkpoint

## Plan
Rule (D-343): `faceChecks` keeps `DEGENERATE_FACE` for every face with area < `minFaceAreaM2`, except a face that is a
verified overhang end cap; the minimum area is then applied to cap + its coplanar end wall. Verification lives in a new
`validate/caps.js`; no tag-only exemption; mathematical degeneracy stays (a degenerate cap is never verified).

The ten conditions of D-343 [D] as numbered here [A: the numbering is this WP's; D-343 lists them as prose]:
- C1 `surfaceKind` WallSurface and tag OVERHANG.
- C2 one outer ring of three vertices, no inner rings (D-337 "vertical triangle").
- C3 non-degenerate: area > `numericEpsilon`, every edge >= `minEdgeLengthM` (mathematical degeneracy kept).
- C4 manifold: every edge has a twin that points back and runs reversed.
- C5 neighbours are exactly one end wall (WallSurface, no OVERHANG), one strip (RoofSurface + OVERHANG), one soffit
  (OuterCeilingSurface + OVERHANG) - the D-336/D-337 profile (`ops/overhang.js` capA = oA -> A -> sA).
- C6 strip and soffit share the edge at the cap's apex (the vertex off the end-wall edge).
- C7 end wall vertical (|n.z| <= `numericEpsilon`, as `ops/overhang.js`).
- C8 coplanar with the end wall: normals equal (dot >= 1 - `numericEpsilon`), |d diff| <= `planarTolM`, every cap
  vertex within `planarTolM` of the end-wall plane.
- C9 no self-intersection of the cap ring and no overlap with the end wall (apex on the far side of the shared edge;
  no crossing of cap and wall edges away from shared vertices; no vertex of one strictly inside the other).
- C10 area(cap) + area(end wall) >= `minFaceAreaM2`.
