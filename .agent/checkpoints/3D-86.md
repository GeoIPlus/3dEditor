Interpretations of README §4 where it does not fix a detail ([A], reported to the owner at finish):
- Percentiles p50/p80: linear interpolation between order statistics (n >= 1).
- WP actual = sum of `cost_usd` of all ledger rows of `kind = wp` for that WP; a class sample = WPs whose row is `done`
  and whose actual is known.
- Current estimate of an open row: newest `Re-estimate` line with `$`, else the `Estimate` line with `$` unless it is a
  `prior` line; a `prior` or missing estimate is recomputed from the ledger with the §3 class fallback
  (Size x Type n>=5 -> Size n>=5 -> all WPs). p80 missing on a line -> class p80.
- Growth g: rows added = row ids in the status table now but not in the BACKLOG of the newest commit older than 14 days;
  rows finished = rows `done` now that were not `done` then (snapshot diff, so merges do not double count).
- Overhead k: (cost of `coord` + `evals` rows + review cost from the `review` column `$x`) / (cost of `wp` rows minus
  their review cost), rows dated in the last 14 days; `other` rows excluded.
