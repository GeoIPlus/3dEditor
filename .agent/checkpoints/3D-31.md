```
exists or not.

Answer in at most 400 words. Every claim about the code carries a path:line reference. Do not guess: if you did not
verify something, say so.
```

### Rubric (10 points, graded on the final answer against the repository; 0 or 1 each)
1. Type registration: `registerCityJsonType` in `apps/viewer-web/client/src/layers/types/cityjson.js` (~:32), called from
   `layers/index.js` (~:73) with `registerLayerType` of `layers/registry.js`.
2. Form handling: `fields` + `fromForm` in `types/cityjson.js` (~:37-54) produce `{ config, data }` (file or URL).
3. Layer creation and parsing: `create()` uses `createVectorLayer` (`types/vector-base.js`); text parsed by
   `parseCityJSON` (`layers/formats/cityjson.js` ~:178), called at `types/cityjson.js` ~:125.
4. "View in 3D": `open3d` / layer action / map marker -> dynamic import of `features/scene3d/index.js` ->
   `openLayer3d` (~:227).
5. 3D content: `features/scene3d/content/cityjson.js` registers `'cityjson'` via `registerContent` (~:142) of
   `content/registry.js`; imported by `scene3d/index.js` (~:22); geometry in `content/model-geometry.js` or `modelData()`.
6. Server plug-in point: `apps/viewer-web/server/src/app.js` composes routers (`create*Router` / `register*Routes`
   imports ~:14-33); a geometry service route would be one more such router.
7. States that no integration of an external edit module / shared components exists in geoviewer today.
8. Proposed client plug-in is consistent with the code: layer `actions()` (`types/cityjson.js` ~:155), a registered
   layer type or scene3d content - and no geometry kernel in the client.
9. Spot-check of at least 5 cited path:line references: all point at what the answer says (+-5 lines).
10. No invented file, function or API (any fabricated name scores 0 here).
