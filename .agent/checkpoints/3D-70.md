Design [A, this WP]:
- `src/adapters/copc-format.js`: COPC info VLR (offset 375, `copc`/1, version bytes 393/394 = 1/0), PDRF 6/7/8 only,
  hierarchy pages (32-byte entries, `pointCount` -1 = child page, 0 = empty), node cube from the key, node-box test.
  Pure functions on bytes (synthetic hierarchy tests without LAZ).
- `src/adapters/copc-points.js`: `createCopcPointsAdapter({ path, read?, decoder? })`; reads the file once (local file;
  HTTP range reads are 3D-61), walks the hierarchy (child pages only when their key meets the box), decodes only
  meeting nodes with `laz-perf` `ChunkDecoder`, exact inclusive box filter (`inBox`), XYZ = int * scale + offset.
- Node cube [A, EPT key naming, which the COPC spec cites; checked empirically on the generated file]: root cube =
  center +/- halfsize; side at level L = 2 halfsize / 2^L; min = root min + (x, y, z) * side.
- `services/*` becomes an npm workspace (root `package.json`, lockfile) so `npm ci` installs `laz-perf` and 3D-67's
  rule finds the root in the lockfile.
- Test data (D-140): `services/kernel/test/data/gt-20.copc.laz`, `gt-21.copc.laz` built once by
  `tools/copc-fixture/make_copc.py` (Python `copclib`, dev-time only, not a dependency of any package) with integer
  coordinates computed in the script so the LAS copy written by `test/las-writer.js` holds the same integers.
  Octree of depth >= 2 so that node selection is meaningful.
- ADR number 0009: 0008 is taken by 3D-12 (`3D-ADR-0008-val3dity-binding.md` on its branch); renumber at merge if needed.
