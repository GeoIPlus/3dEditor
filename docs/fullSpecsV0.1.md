# ЧАСТЬ I. ОСНОВНОЕ ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## Введение и архитектурная предпосылка

**Назначение документа:** структурированный перечень функций для разработки онлайн-инструмента коррекции LOD2/LOD3-моделей по облакам точек и косым аэрофотоснимкам с целью получения геометрически точных моделей для налоговой оценки. Каждая функция описана по единому шаблону: **назначение → исходные данные → действия оператора → результат → технические требования**.

**Архитектурная предпосылка:** ядро данных — **Roof Topology Graph (RTG)** с параметрической декомпозицией ячеек, а не треугольная сетка. Все операции редактирования выполняются над графом топологии с обязательной пост-валидацией по ISO 19107 (val3dity, индекс инцидентности c(e) = 2).

**Ключевой принцип:** ни одна операция редактирования не завершается без автоматического вызова валидатора. Нарушение watertightness напрямую искажает расчёт объёма и делает модель непригодной для налоговой оценки.

## Модуль 1. Импорт и управление исходными данными

### F-01. Загрузка облака точек
- **Назначение:** приём исходного облака точек для последующей привязки и корректировки модели.
- **Исходные данные:** файлы LAS/LAZ, E57, PLY, TXT/XYZ; опционально — проприетарные форматы (LiData, RWP, TZF).
- **Действия оператора:** 1) выбрать файл(ы) через drag-and-drop или файловый менеджер; 2) указать систему координат (EPSG) или подтвердить автоопределение; 3) запустить фоновую загрузку; 4) по завершении проверить статистику (число точек, bounding box, плотность точек/м²).
- **Результат:** облако точек доступно в рабочей сцене как отдельный слой с метаданными (CRS, плотность, источник).
- **Технические требования:** поддержка файлов >10 ГБ через потоковую загрузку; автоматическое построение octree/LOD-пирамиды для рендеринга; предупреждение, если плотность <8 точек/м² (порог roofer/3DBAG).

### F-02. Загрузка исходной LOD2/LOD3-модели
- **Назначение:** приём модели, подлежащей корректировке.
- **Исходные данные:** CityGML (0.4–3.0), CityJSON, OBJ, DXF, SHP (Multipatch), 3D Tiles, OSGB, glTF.
- **Действия оператора:** 1) загрузить файл; 2) выбрать целевой LOD и подтвердить маппинг семантических типов (RoofSurface, WallSurface, GroundSurface, BuildingInstallation); 3) указать, является ли модель «чистой» (watertight) или требует предварительной починки.
- **Результат:** модель загружена, разложена на семантические части, готова к редактированию в RTG.
- **Технические требования:** автоматическая проверка на watertightness при импорте; отчёт о найденных дефектах (дыры, самопересечения, непланарные грани); сохранение исходной геометрии как «эталонной» для Maintenance Mode.

### F-03. Загрузка косых и плановых аэрофотоснимков
- **Назначение:** обеспечение стереоизмерений и текстурирования.
- **Исходные данные:** снимки (TIFF/JPEG) + метаданные: EO-параметры (X, Y, Z, ω, φ, κ), внутреннее ориентирование (фокусное расстояние, размер пикселя, principal point), опционально — GNSS/IMU.
- **Действия оператора:** 1) загрузить пакет снимков и файл метаданных; 2) подтвердить параметры камеры; 3) запустить автоматическое построение стереопар по перекрытию; 4) проверить качество привязки (визуально — совпадение с облаком точек).
- **Результат:** снимки доступны в режиме стереопросмотра и как текстуры для проецирования.
- **Технические требования:** поддержка форматов EO (Bingo, Pix4D, Metashape, UltraMap); автоматический расчёт стереопар по overlap ≥60%; возможность ручной корректировки EO-параметров.

### F-04. Загрузка векторных контуров (footprints)
- **Назначение:** использование кадастровых или эталонных контуров как опорной геометрии.
- **Исходные данные:** SHP, GeoJSON, DXF, CSV с координатами.
- **Действия оператора:** 1) загрузить файл; 2) указать поле с ID здания; 3) сопоставить контуры с загруженной моделью (автоматически по пространственному пересечению или вручную).
- **Результат:** контуры отображаются как отдельный слой; доступны для операций сравнения (F-46) и выравнивания (F-30).
- **Технические требования:** поддержка 2D и 3D-полигонов; автоматическая валидация геометрии (замкнутость, отсутствие самопересечений).

### F-05. Управление слоями и рабочими наборами
- **Назначение:** раздельное отображение и управление видимостью разнородных данных.
- **Исходные данные:** загруженные слои (облако, модель, снимки, векторы).
- **Действия оператора:** 1) открыть панель слоёв; 2) включать/выключать видимость; 3) настраивать прозрачность, цвет, стиль отображения; 4) сохранять комбинации как «рабочие наборы» (например, «только крыша + облако»).
- **Результат:** настроенные рабочие наборы, переключаемые в один клик.
- **Технические требования:** сохранение состояния слоёв в проекте; поддержка до 50 слоёв без просадки FPS.

### F-06. Пакетная загрузка и фоновые задачи
- **Назначение:** обработка больших массивов данных (тысячи зданий).
- **Исходные данные:** архивы или наборы файлов.
- **Действия оператора:** 1) выбрать пакет; 2) настроить очередь (приоритеты, лимиты ресурсов); 3) отслеживать прогресс в панели задач.
- **Результат:** данные загружены и поставлены в очередь на обработку.
- **Технические требования:** фоновая обработка без блокировки интерфейса; возобновление после сбоя; журнал операций.

### F-07. Управление проектами и версиями
- **Назначение:** организация работы над несколькими проектами/районами.
- **Исходные данные:** метаданные проекта (название, район, заказчик, дата).
- **Действия оператора:** 1) создать проект; 2) задать параметры (CRS, целевой LOD, стандарт — CityGML 2.0/3.0); 3) пригласить участников; 4) переключаться между проектами.
- **Результат:** изолированные рабочие пространства с собственной историей.
- **Технические требования:** облачное хранение; история версий; возможность отката к любой точке сохранения.

### F-08. Экспорт исходного состояния (baseline)
- **Назначение:** фиксация «как было» до редактирования для последующего сравнения.
- **Исходные данные:** текущая модель.
- **Действия оператора:** 1) нажать «Зафиксировать baseline»; 2) указать комментарий.
- **Результат:** снимок модели сохранён; доступен для сравнения (F-47) и отката.
- **Технические требования:** хранение в неизменяемом виде; автоматическая маркировка версии.

## Модуль 2. Визуализация и навигация

### F-09. Рендеринг облака точек с LOD
- **Назначение:** производительное отображение плотных облаков в браузере.
- **Исходные данные:** загруженное облако точек.
- **Действия оператора:** 1) выбрать режим отображения (точки, круги, кубы); 2) настроить размер и цвет (по высоте, по интенсивности, по классификации); 3) управлять плотностью через ползунок «качество/производительность».
- **Результат:** интерактивное облако с автоматическим прореживанием при навигации и полной детализацией при приближении.
- **Технические требования:** octree-структура; целевой FPS ≥30 на сценах до 10 млрд точек; WebGL2/WebGPU.

### F-10. Срезы и ограничивающие боксы (Clipping)
- **Назначение:** изоляция участка работ и скрытие шума.
- **Исходные данные:** текущая сцена.
- **Действия оператора:** 1) активировать инструмент «Clipping Box»; 2) задать бокс (мышью или числовыми координатами); 3) выбрать — скрывать внутри или снаружи; 4) сохранить как именованный срез.
- **Результат:** видимая только нужная часть данных.
- **Технические требования:** до 10 одновременных боксов; срезы применяются ко всем слоям или выборочно.

### F-11. Быстрый срез с автовыравниванием UCS (QuickSlice)
- **Назначение:** мгновенное сечение и ориентация системы координат по стене или полу.
- **Исходные данные:** облако точек или модель.
- **Действия оператора:** 1) выбрать инструмент; 2) указать 1–3 точки на стене/полу; 3) подтвердить — UCS автоматически ориентируется по нормали.
- **Результат:** вид «в плане» или «в разрезе» относительно выбранной плоскости.
- **Технические требования:** точность ориентации ≤0,5°; немедленное переключение камеры.

### F-12. Многовидовой режим
- **Назначение:** одновременная работа в нескольких проекциях.
- **Исходные данные:** текущая сцена.
- **Действия оператора:** 1) выбрать раскладку (2, 3, 4 вида); 2) назначить виды (перспектива, top, изометрия, камера снимка); 3) синхронизировать навигацию.
- **Результат:** синхронизированные виды, изменения отражаются во всех окнах.
- **Технические требования:** синхронизация курсора и выделения; независимая навигация по желанию.

### F-13. Навигация и закладки
- **Назначение:** быстрое перемещение между зданиями и ракурсами.
- **Исходные данные:** координаты или выделенные объекты.
- **Действия оператора:** 1) создать закладку (Ctrl+B); 2) назвать; 3) переключаться через список.
- **Результат:** сохранённые ракурсы.
- **Технические требования:** привязка закладок к ID здания; экспорт/импорт списка.

### F-14. Отображение и настройка солнца/теней
- **Назначение:** визуальная проверка геометрии по теням.
- **Исходные данные:** координаты и дата.
- **Действия оператора:** 1) задать дату/время; 2) включить тени; 3) сравнить тень модели с тенью на снимке.
- **Результат:** визуальная валидация силуэта.
- **Технические требования:** расчёт по солнечному алгоритму; сравнение с ортофото.

### F-15. Режим «только каркас» и наложение
- **Назначение:** контроль совпадения модели с облаком.
- **Исходные данные:** модель + облако.
- **Действия оператора:** 1) включить каркасный режим модели; 2) настроить прозрачность облака; 3) визуально оценить расхождения.
- **Результат:** наглядное сравнение геометрии.
- **Технические требования:** цветовая индикация отклонений (например, heatmap расстояний).

## Модуль 3. Редактирование топологии крыши (ядро)

### F-16. Автоматическое построение Roof Topology Graph (RTG)
- **Назначение:** преобразование импортированной модели в редактируемый граф топологии.
- **Исходные данные:** загруженная LOD2-модель (или облако + контур).
- **Действия оператора:** 1) запустить «Построить RTG»; 2) проверить автоматически найденные плоскости скатов; 3) при необходимости объединить/разделить ячейки (F-17, F-18).
- **Результат:** модель представлена как набор параметрических ячеек с общими рёбрами и вершинами; все грани — плоские, тело — watertight.
- **Технические требования:** алгоритм кластеризации плоскостей (RANSAC/регион-рост); допуск на планарность (по умолчанию 2 см); гарантия c(e) = 2 для каждого ребра.

### F-17. Разбиение ячейки (Split Cell)
- **Назначение:** разделение одного ската на несколько.
- **Исходные данные:** выбранная ячейка RTG.
- **Действия оператора:** 1) выбрать ячейку; 2) провести линию разбиения по двум точкам (с привязкой к облаку или снимку); 3) подтвердить.
- **Результат:** две смежные ячейки с общим ребром; обе плоские.
- **Технические требования:** автоматическое вычисление линии пересечения плоскостей; сохранение watertightness.

### F-18. Объединение ячеек (Merge Cells)
- **Назначение:** устранение паразитных фасетов, порождённых SGM/AI.
- **Исходные данные:** две и более смежных ячейки.
- **Действия оператора:** 1) выделить ячейки; 2) нажать «Объединить»; 3) проверить плоскость результата.
- **Результат:** одна ячейка; удалены ложные рёбра.
- **Технические требования:** проверка копланарности (допуск); отказ при несовместимости.

### F-18a. Удаление мелких фасетов (Remove Details)
- **Назначение:** массовая очистка паразитных мелких полигонов.
- **Исходные данные:** выделенная область или всё здание.
- **Действия оператора:** 1) задать порог площади (например, <0,5 м²); 2) запустить; 3) подтвердить список найденных фасетов.
- **Результат:** мелкие фасеты удалены или объединены с соседними.
- **Технические требования:** отчёт «до/после»; откат.

### F-19. Выравнивание конька (ridge) по новой линии
- **Назначение:** приведение конька к прямой, заданной оператором или облаком.
- **Исходные данные:** две смежные ячейки, образующие конёк; опционально — 2–3 точки на облаке или снимке.
- **Действия оператора:** 1) выбрать ребро конька; 2) указать новую линию (две точки на облаке/снимке или числовые координаты); 3) подтвердить — система фиксирует плоскости смежных скатов и вычисляет новую линию их пересечения.
- **Результат:** конёк выровнен; смежные скаты остались плоскими; углы наклона пересчитаны.
- **Технические требования:** аналитическое пересечение плоскостей (аналог Apply Intersection Line); сохранение планарности и c(e) = 2; пересчёт высот карниза.

### F-20. Выравнивание карниза (eave) по новой линии
- **Назначение:** аналогично F-19, но для нижней границы ската.
- **Исходные данные:** ячейка + новая линия карниза.
- **Действия оператора:** 1) выбрать ребро карниза; 2) задать новую линию; 3) подтвердить.
- **Результат:** карниз выровнен; примыкающие стены обновлены.
- **Технические требования:** автоматическое обновление WallSurface под новым карнизом; проверка высоты eave.

### F-21. Подгонка ячейки к общему ребру (Fit Cell to Incident Edge)
- **Назначение:** автоматическая подстройка высот конька и карниза одной ячейки под соседнюю по общему ребру.
- **Исходные данные:** выбранная ячейка + общее ребро с соседней.
- **Действия оператора:** 1) нажать на общее ребро; 2) система сэмплирует соседнюю плоскость в крайних точках; 3) подтвердить.
- **Результат:** высоты конька/карниза согласованы; щели устранены.
- **Технические требования:** один клик; сохранение планарности обеих ячеек; откат.

### F-22. Согласование вершин при схождении ≥3 скатов (Multi-Cell Vertex Alignment)
- **Назначение:** устранение щелей в узлах, где сходятся 3+ ячейки.
- **Исходные данные:** общая вершина + список примыкающих ячеек.
- **Действия оператора:** 1) выбрать вершину; 2) запустить «Согласовать»; 3) система ищет 2D-позицию, при которой все плоскости сходятся на одной Z; 4) подтвердить.
- **Результат:** все ячейки смыкаются без щелей.
- **Технические требования:** решение системы уравнений; допуск по Z (по умолчанию 1 см).

### F-23. Ортогональная привязка (Orthogonal Snapping)
- **Назначение:** принудительная привязка перемещаемых вершин/линий под 0°/90° к главному направлению.
- **Исходные данные:** активное ребро/вершина + опорное направление (ребро стены, контур).
- **Действия оператора:** 1) включить режим; 2) выбрать опорное ребро; 3) перемещать — курсор «магнитится» к 0°/90°; 4) зафиксировать.
- **Результат:** ортогональная геометрия без ручной подгонки.
- **Технические требования:** динамическая привязка; индикация угла; отключение по Esc.

### F-24. Выпрямление ячейки (Straighten Cell)
- **Назначение:** сведение ячеек с >4 вершинами к четырёхугольной форме.
- **Исходные данные:** выбранная ячейка.
- **Действия оператора:** 1) выбрать; 2) нажать «Выпрямить»; 3) проверить результат.
- **Результат:** четырёхугольная ячейка; смежные грани не разорваны.
- **Технические требования:** минимизация отклонения от исходных вершин; сохранение watertightness.

### F-25. Перемещение ребра / вершины с фиксацией (Move Edge / Move Vertex)
- **Назначение:** точное перемещение элементов RTG.
- **Исходные данные:** ребро или вершина.
- **Действия оператора:** 1) выделить; 2) задать смещение (мышью или числовые X/Y/Z); 3) отметить опорные точки как «Fixed»; 4) подтвердить — остальной контур пересчитывается относительно Fixed.
- **Результат:** элемент сдвинут; примыкающие грани перестроены; Fixed-точки неподвижны.
- **Технические требования:** числовой ввод; сохранение планарности; откат.

### F-26. Прямоугольный вырез части крыши (Rectangular Cut)
- **Назначение:** вырезание прямоугольного участка крыши (Г-образные сочленения, врезки).
- **Исходные данные:** крыша (ячейка/набор ячеек) + плоскость реза.
- **Действия оператора:** 1) включить Orthogonal Snapping (F-23); 2) нарисовать прямоугольный контур на скате; 3) выбрать — понизить высоту вырезанного сегмента или удалить; 4) подтвердить.
- **Результат:** прямоугольный вырез; торцевые стенки построены автоматически.
- **Технические требования:** аналог Slice Multipatch + Orthogonal Snapping; автозамыкание граней; c(e) = 2.

### F-27. Вырезание угла / сегмента ребра (Cut Edge Corner / Segment)
- **Назначение:** ступенчатые фасады крыш, скосы углов.
- **Исходные данные:** ребро/угол.
- **Действия оператора:** 1) выбрать ребро/угол; 2) указать линию реза; 3) подтвердить.
- **Результат:** угол/сегмент вырезан; смежные грани перестроены.
- **Технические требования:** сохранение watertightness; откат.

### F-28. Построение ступенчатого угла (Build Step Corner)
- **Назначение:** формирование ступенек на фасаде/крыше.
- **Исходные данные:** угол/ребро + параметры ступеньки (высота, ширина).
- **Действия оператора:** 1) выбрать угол; 2) задать параметры; 3) подтвердить.
- **Результат:** ступенчатый угол.
- **Технические требования:** параметрическая генерация; сохранение c(e) = 2.

### F-29. Расширение крыши — режим «габарит»
- **Назначение:** изменение основного габарита здания с пересчётом скатов.
- **Исходные данные:** контур крыши + новое положение рёбер.
- **Действия оператора:** 1) выбрать режим «Габарит»; 2) переместить внешние рёбра (F-25); 3) подтвердить — система пересчитывает пересечения скатов.
- **Результат:** крыша расширена; скаты плоские; стены обновлены.
- **Технические требования:** аналитическое пересечение плоскостей; сохранение watertightness.

### F-30. Расширение крыши — режим «Свес» (Overhang)
- **Назначение:** независимое выдвижение карнизного полигона наружу относительно неподвижного контура стен.
- **Исходные данные:** контур стен (неподвижный) + карнизный полигон.
- **Действия оператора:** 1) выбрать режим «Свес»; 2) задать величину вылета (числом или мышью); 3) подтвердить.
- **Результат:** свес смоделирован как отдельный элемент; площадь застройки (по контуру стен) **не изменилась**.
- **Технические требования:** разделение WallSurface и Overhang (по AdV); обязательная маркировка Overhang при вылете >1–3 м; соответствие CityGML 3.0 (OccupiedSpace).

### F-31. Сдвиг ячейки по нормали (Offset Cell)
- **Назначение:** параллельный перенос ската без изменения угла наклона.
- **Исходные данные:** ячейка + величина смещения.
- **Действия оператора:** 1) выбрать; 2) задать смещение; 3) подтвердить.
- **Результат:** ячейка сдвинута; примыкающие грани перестроены.
- **Технические требования:** сохранение планарности; проверка на пересечения.

### F-32. Симметрия плоскости (Plane Symmetry)
- **Назначение:** зеркальное отражение ячейки относительно плоскости.
- **Исходные данные:** ячейка + плоскость симметрии.
- **Действия оператора:** 1) выбрать ячейку; 2) указать плоскость (по 3 точкам или существующей грани); 3) подтвердить.
- **Результат:** зеркальная копия; исходная сохранена или заменена.
- **Технические требования:** сохранение watertightness; откат.

### F-33. Удаление ячейки (Remove Cell)
- **Назначение:** удаление лишнего ската/патча.
- **Исходные данные:** выбранная ячейка.
- **Действия оператора:** 1) выделить; 2) нажать «Удалить»; 3) подтвердить — система автоматически замыкает образовавшееся отверстие.
- **Результат:** ячейка удалена; тело осталось watertight.
- **Технические требования:** автозамыкание; проверка c(e) = 2.

### F-34. Принудительное выравнивание высот смежных вершин (Match Roof Elevations)
- **Назначение:** устранение расхождений по Z между смежными ячейками.
- **Исходные данные:** группа смежных вершин.
- **Действия оператора:** 1) выделить вершины; 2) нажать «Выровнять по Z»; 3) выбрать целевую высоту (средняя/мин/макс/числовая).
- **Результат:** все вершины на одной Z.
- **Технические требования:** сохранение планарности смежных граней.

### F-35. Разделение здания на части (Split Building / BuildingPart)
- **Назначение:** выделение пристроек, секций, BuildingPart.
- **Исходные данные:** здание + линия/плоскость разбиения.
- **Действия оператора:** 1) выбрать линию разбиения; 2) подтвердить — система создаёт два BuildingPart с общей границей.
- **Результат:** два независимых объекта с сохранением watertightness каждого.
- **Технические требования:** семантика BuildingPart (CityGML); сохранение адресов xAL.

### F-36. Добавление дормера / слухового окна (Add Dormer)
- **Назначение:** полуавтоматическая вставка дормера уровня LOD3.
- **Исходные данные:** участок ската (обведён оператором) + облако точек / снимки.
- **Действия оператора:** 1) обвести участок на скате; 2) выбрать тип (плоская/двускатная кровля); 3) запустить — система выполняет высотную кластеризацию + RANSAC, находит выступающие точки, вписывает параметрический примитив; 4) при необходимости скорректировать размеры; 5) подтвердить.
- **Результат:** дормер как отдельный `BuildingInstallation`; основание подрезано строго по наклону несущего ската.
- **Технические требования:** RANSAC + height clustering; параметрическая подрезка; семантика BuildingInstallation; проверка watertightness.

### F-37. Добавление трубы / вентшахты (Add Chimney)
- **Назначение:** вставка трубы уровня LOD3.
- **Исходные данные:** участок ската + облако/снимки.
- **Действия оператора:** 1) указать точку на скате; 2) выбрать тип (параллелепипед, цилиндр); 3) задать размеры (или взять из облака автоматически); 4) подтвердить.
- **Результат:** труба как `BuildingInstallation` с подрезкой основания по скату.
- **Технические требования:** автоматическое определение высоты по облаку; семантика; watertightness.

### F-38. Добавление проёма (окно/люк) булевым объектом
- **Назначение:** создание проёмов в крыше/стене.
- **Исходные данные:** грань + контур проёма.
- **Действия оператора:** 1) выбрать грань; 2) нарисовать контур; 3) задать глубину; 4) подтвердить.
- **Результат:** проём с семантикой `Window`/`Door` или `Opening`.
- **Технические требования:** булева операция; сохранение watertightness; семантика CityGML.

## Модуль 4. Редактирование элементов здания (стены, контуры, высоты)

### F-39. Редактирование контура здания (Footprint Regularization)
- **Назначение:** приведение контура к корректной форме.
- **Исходные данные:** контур здания.
- **Действия оператора:** 1) выбрать контур; 2) запустить «Регуляризация» — система спрямляет близкие к прямым участки, удаляет шумовые вершины, устраняет отверстия; 3) при необходимости доработать вручную.
- **Результат:** ортогонализованный контур.
- **Технические требования:** допуск на спрямление (по умолчанию 5°); отчёт об изменениях.

### F-40. Выравнивание стен (Wall Alignment)
- **Назначение:** подгонка вертикальных плоскостей стен под облако/новую линию карниза.
- **Исходные данные:** стена + опорная линия или облако.
- **Действия оператора:** 1) выбрать стену; 2) указать опорную линию (по облаку/снимку); 3) подтвердить.
- **Результат:** стена выровнена; примыкающие крыша/пол перестроены.
- **Технические требования:** сохранение watertightness; пересчёт eave height.

### F-41. Изменение высотных отметок (Base / Eave Height)
- **Назначение:** корректировка базовой отметки или высоты карниза.
- **Исходные данные:** здание + новое значение.
- **Действия оператора:** 1) выбрать параметр (base/eave); 2) ввести новое значение (или взять из облака); 3) подтвердить.
- **Результат:** отметка изменена; объём пересчитан.
- **Технические требования:** автоматический пересчёт объёма и площади; отчёт.

### F-42. Перемещение здания как единого объекта
- **Назначение:** устранение систематического сдвига модели относительно кадастра.
- **Исходные данные:** здание + вектор смещения.
- **Действия оператора:** 1) выделить всё здание; 2) задать смещение (X/Y/Z, число); 3) подтвердить.
- **Результат:** здание сдвинуто; внутренняя структура сохранена.
- **Технические требования:** сохранение watertightness; пересчёт координат.

### F-43. Поворот здания
- **Назначение:** коррекция ориентации.
- **Исходные данные:** здание + ось и угол.
- **Действия оператора:** 1) выбрать ось; 2) задать угол; 3) подтвердить.
- **Результат:** здание повёрнуто.
- **Технические требования:** сохранение watertightness.

## Модуль 5. Работа с косыми снимками и стерео

### F-44. Режим «3D-модель + стереоизображение»
- **Назначение:** одновременный показ модели, облака и стереопары.
- **Исходные данные:** модель + стереопара + EO-параметры.
- **Действия оператора:** 1) выбрать стереопару; 2) включить стереорежим (анаглиф/полярные очки); 3) работать в 3D-виде.
- **Результат:** синхронизированный просмотр; изменения геометрии сразу видны на стерео.
- **Технические требования:** синхронизация камер; поддержка passive/active stereo.

### F-45. Стереоизмерение («плавающая марка»)
- **Назначение:** снятие точных 3D-координат по стереопаре.
- **Исходные данные:** стереопара.
- **Действия оператора:** 1) активировать «плавающую марку»; 2) навести на точку; 3) зафиксировать — координаты X/Y/Z записаны; 4) использовать для позиционирования вершины (F-19, F-20).
- **Результат:** точка с 3D-координатами, привязанная к модели.
- **Технические требования:** точность ≤2 пикселей; экспорт координат.

### F-46. Проецирование текстур со снимков
- **Назначение:** автоматическое наложение текстур.
- **Исходные данные:** модель + снимки + EO.
- **Действия оператора:** 1) выбрать грани; 2) запустить «Проецировать»; 3) при необходимости выбрать снимок вручную (при конфликтах).
- **Результат:** текстурированная модель.
- **Технические требования:** выбор лучшего снимка по углу и разрешению; blending на стыках.

### F-47. Ручная корректировка текстуры
- **Назначение:** замена/уточнение текстуры на отдельных гранях.
- **Исходные данные:** грань + новый снимок.
- **Действия оператора:** 1) выбрать грань; 2) выбрать снимок; 3) настроить проекцию.
- **Результат:** обновлённая текстура.
- **Технические требования:** предпросмотр в реальном времени.

### F-48. Сравнение модели с облаком (Inspection / Heatmap)
- **Назначение:** количественная оценка расхождений.
- **Исходные данные:** модель + облако.
- **Действия оператора:** 1) запустить «Сравнить»; 2) настроить порог; 3) просмотреть heatmap; 4) перейти к проблемным зонам.
- **Результат:** карта отклонений + отчёт (RMSE, max, распределение).
- **Технические требования:** расчёт расстояний point-to-surface; цветовая шкала.

### F-49. Редактирование по снимкам «вслепую»
- **Назначение:** корректировка геометрии в местах, где облако разрежено.
- **Исходные данные:** снимок + модель.
- **Действия оператора:** 1) переключиться на вид снимка; 2) указать положение ребра/конька на снимке; 3) система проецирует на модель; 4) подтвердить.
- **Результат:** геометрия скорректирована по снимку.
- **Технические требования:** обратная проекция луча; учёт окклюзий.

## Модуль 6. Семантика и атрибуты

### F-50. Назначение семантических типов поверхностей (CityGML)
- **Назначение:** классификация граней.
- **Исходные данные:** грани модели.
- **Действия оператора:** 1) выбрать грани; 2) назначить тип (RoofSurface, WallSurface, GroundSurface, ClosureSurface, Overhang); 3) подтвердить.
- **Результат:** грани классифицированы.
- **Технические требования:** соответствие CityGML 2.0/3.0; валидация обязательных типов.

### F-51. Назначение объектных типов
- **Назначение:** классификация объектов.
- **Исходные данные:** объекты модели.
- **Действия оператора:** 1) выбрать объект; 2) назначить тип (Building, BuildingPart, BuildingInstallation, Window, Door); 3) подтвердить.
- **Результат:** объекты классифицированы.
- **Технические требования:** иерархия CityGML; проверка вложенности.

### F-52. Редактирование атрибутов
- **Назначение:** ручное заполнение/корректировка атрибутов.
- **Исходные данные:** объект + список атрибутов.
- **Действия оператора:** 1) открыть панель атрибутов; 2) отредактировать значения; 3) сохранить.
- **Результат:** обновлённые атрибуты.
- **Технические требования:** валидация типов; история изменений.

### F-53. Автоматический расчёт метрик
- **Назначение:** вычисление площадей, объёмов, высот.
- **Исходные данные:** геометрия модели.
- **Действия оператора:** 1) нажать «Рассчитать»; 2) выбрать набор метрик.
- **Результат:** таблица: площадь застройки (по контуру стен), площадь крыши, объём (OccupiedSpace), eave height, ridge height.
- **Технические требования:** раздельный расчёт по контуру стен и по свесу (Overhang); соответствие CityGML 3.0 (OccupiedSpace / UnoccupiedSpace); точность ≤1%.

### F-54. Управление адресами и внешними ссылками (xAL)
- **Назначение:** сохранение адресных данных при редактировании.
- **Исходные данные:** xAL-атрибуты.
- **Действия оператора:** 1) проверить/отредактировать; 2) подтвердить.
- **Результат:** адреса сохранены.
- **Технические требования:** соответствие xAL; сохранение при Split Building (F-35).

## Модуль 7. Валидация и контроль качества

### F-55. Пост-валидация геометрии (val3dity / ISO 19107)
- **Назначение:** автоматическая проверка после каждого редактирования.
- **Исходные данные:** текущая модель.
- **Действия оператора:** 1) валидация запускается автоматически; 2) просмотреть отчёт; 3) перейти к ошибкам.
- **Результат:** отчёт: все рёбра `GM_Curve` линейны; грани `GM_Surface` плоские в допуске; каждое тело `Solid` — 2-многообразие; **c(e) = 2** для всех рёбер; флаги для c(e) = 1 (дыры) и c(e) ≠ 2 (не-манифолд).
- **Технические требования:** интеграция val3dity; блокировка экспорта при критических ошибках.

### F-56. Проверка watertightness
- **Назначение:** отдельная проверка замкнутости тел.
- **Исходные данные:** модель.
- **Действия оператора:** 1) запустить; 2) просмотреть список незамкнутых тел.
- **Результат:** список дефектов с переходом к ним.
- **Технические требования:** алгоритм обхода границ; отчёт.

### F-57. Проверка планарности граней
- **Назначение:** выявление непланарных полигонов.
- **Исходные данные:** модель.
- **Действия оператора:** 1) запустить; 2) задать допуск; 3) просмотреть.
- **Результат:** список граней с отклонением > допуска.
- **Технические требования:** расчёт отклонения от плоскости; подсветка.

### F-58. Сравнение с baseline (F-08)
- **Назначение:** количественная оценка правок.
- **Исходные данные:** текущая + baseline.
- **Действия оператора:** 1) запустить сравнение; 2) просмотреть отчёт (изменения объёма, площади, геометрии).
- **Результат:** отчёт «до/после».
- **Технические требования:** расчёт RMSE, diff по метрикам.

### F-59. Сравнение с кадастровым контуром
- **Назначение:** выявление смещений относительно реестра.

  isFixed: boolean;    // F-25: защита от автопересчёта

## Приложение C. Конкретные алгоритмы операций

### C.1. F-19 / F-20. Выравнивание конька (ridge) или карниза (eave) по новой линии

**Вход:** две смежные ячейки `C1`, `C2`, общее ребро `E`, новая линия `L_new` (2 точки или числовые координаты).

**Метод:** аналитическое пересечение плоскостей + пересчёт плоскостей при фиксации противоположного ребра.

**Псевдокод:**

```
function alignRidge(C1, C2, E, L_new):
    # 1. Валидация: L_new должна быть коллинеарна текущему направлению E
    #    (иначе — предупреждение о скручивании скатов)
    d_old = normalize(E.end.coords - E.start.coords)
    d_new = normalize(L_new.p2 - L_new.p1)
    if angle(d_old, d_new) > 5°:
        warn("Ridge direction changed — adjacent slopes will be recomputed")

    # 2. Для каждой ячейки: зафиксировать противоположное ребро (eave или boundary)
    for Ci in [C1, C2]:
        opp_edge = findOppositeEdge(Ci, E)   # ребро, не инцидентное E
        if opp_edge is None:
            raise("Cannot align: no fixed opposite edge")
        p_opp_a = vertices[opp_edge.start].coords
        p_opp_b = vertices[opp_edge.end].coords

        # 3. Пересчитать плоскость через L_new и opp_edge (3 точки → плоскость)
        #    Используем SVD для устойчивости при коллинеарности
        points = [L_new.p1, L_new.p2, p_opp_a, p_opp_b]
        plane_new = fitPlaneSVD(points)     # Ax+By+Cz+D=0, нормировано

        # 4. Проверка: все вершины Ci должны лежать в plane_new с допуском
        for v in Ci.vertices:
            if distanceToPlane(v.coords, plane_new) > tol.planar:
                v.coords = projectToPlane(v.coords, plane_new)

        Ci.plane = plane_new
        Ci.slope = acos(abs(plane_new.c)) * 180/pi

    # 5. Обновить общие вершины C1 и C2 (новые концы E)
    E.start.coords = L_new.p1
    E.end.coords   = L_new.p2

    # 6. Рекурсивно пересчитать соседние ячейки, если их вершины затронуты
    for neighbor in getAdjacentCells(C1) + getAdjacentCells(C2):
        if sharesAnyVertex(neighbor, E):
            recomputeCellFromFixedEdges(neighbor)

    # 7. Пост-валидация
    return validate(RTG)
```

**Ключевой момент:** если оператор меняет только *высоту* конька (сдвиг по Z), плоскости скатов пересчитываются через `fitPlaneSVD` с фиксацией карниза. Если меняется *направление* конька — обязательно предупреждение, т.к. это меняет углы наклона.

**Библиотеки:** `numpy.linalg.svd`, `scipy.spatial.distance`.

### C.2. F-21. Fit Cell to Incident Edge

**Метод:** сэмплирование соседней плоскости в двух крайних точках общего ребра + решение системы линейных уравнений для высот.

```
function fitCellToIncidentEdge(C_target, E_shared, C_neighbor):
    p_a = vertices[E_shared.start].coords
    p_b = vertices[E_shared.end].coords
    z_a_neighbor = solveZ(C_neighbor.plane, p_a.x, p_a.y)
    z_b_neighbor = solveZ(C_neighbor.plane, p_b.x, p_b.y)

    z_a_target = (p_a.z + z_a_neighbor) / 2
    z_b_target = (p_b.z + z_b_neighbor) / 2

    opp_a, opp_b = findOppositeEdge(C_target, E_shared)
    points = [(p_a.x, p_a.y, z_a_target), (p_b.x, p_b.y, z_b_target),
              opp_a.coords, opp_b.coords]
    C_target.plane = fitPlaneLSQ(points)   # least squares
    return validate(RTG)
```

### C.3. F-22. Multi-Cell Shed Vertex Alignment

**Метод:** решение нелинейной системы (в общем случае) или сведение к линейной через линеаризацию.

Для вершины `v`, общей для `k ≥ 3` ячеек `C1..Ck`, нужно найти `(x, y, z)` такое, что `z = plane_i(x, y)` для всех `i`. То есть:

```
z = a_i*x + b_i*y + d_i   (из plane_i: a_i*x + b_i*y + c_i*z + d_i = 0 → z = -(a_i*x + b_i*y + d_i)/c_i)
```

**Система:** `A·[x,y]ᵀ = b`, где каждая строка `i` = `[a_i/c_i - a_1/c_1, b_i/c_i - b_1/c_1]`, `b_i = d_1/c_1 - d_i/c_i`.

**Решение:** `numpy.linalg.lstsq` (переопределённая система, если k > 3 — минимизация невязки).

```python
def multiCellVertexAlign(vertex, cells):
    A, b = [], []
    ref = cells[0].plane
    for cell in cells[1:]:
        p = cell.plane
        A.append([p.a/p.c - ref.a/ref.c, p.b/p.c - ref.b/ref.c])
        b.append(ref.d/ref.c - p.d/p.c)
    xy = np.linalg.lstsq(np.array(A), np.array(b), rcond=None)[0]
    vertex.coords = (xy[0], xy[1], solveZ(ref, xy[0], xy[1]))
    return validate(RTG)
```

Если `lstsq` даёт невязку > `tol.zAlign` — оператору возвращается предупреждение «вершины не могут быть согласованы без изменения плоскостей; выберите, какую ячейку подстроить».

### C.4. F-24. Straighten Cell

**Метод:** проекция вершин на плоскость ячейки → minimum-area bounding rectangle (rotating calipers) → выбор 4 углов → snap к соседним ячейкам.

```python
def straightenCell(cell):
    pts_2d = [projectToPlane2D(v, cell.plane) for v in cell.vertices]
    rect = cv2.minAreaRect(np.array(pts_2d, dtype=np.float32))
    corners = cv2.boxPoints(rect)
    new_vertices = [unprojectFromPlane2D(c, cell.plane) for c in corners]
    for edge in cell.edges:
        neighbor = getNeighbor(edge, cell)
        for v_id in (edge.start_vertex_id, edge.end_vertex_id):
            nearest = argmin(dist(vertices[v_id].coords, new_vertices))
            vertices[v_id].coords = new_vertices[nearest]
    cell.plane = fitPlaneSVD(new_vertices)
    return validate(RTG)
```

**Альтернатива:** RANSAC по рёбрам (`open3d`), если ячейка сильно зашумлена.

### C.5. F-25. Move Edge / Vertex with Fixed constraints

**Метод:** применение дельты + пересчёт зависимых ячеек через least squares с фиксацией `isFixed`-вершин.

```python
def moveEdge(edge, delta, fixed_vertices: set[str]):
    for v_id in (edge.start_vertex_id, edge.end_vertex_id):
        if v_id not in fixed_vertices:
            vertices[v_id].coords = add(vertices[v_id].coords, delta)

    dependent = [c for c in cells.values() if edge.id in c.edge_ids]

    for cell in dependent:
        free_pts = [vertices[v].coords for v in cell.vertex_ids if v not in fixed_vertices]
        fixed_pts = [vertices[v].coords for v in cell.vertex_ids if v in fixed_vertices]
        if len(fixed_pts) >= 3:
            cell.plane = fitPlaneSVD(fixed_pts)
        elif len(fixed_pts) == 2:
            cell.plane = fitPlaneConstrained(fixed_pts, original_plane=cell.plane)
        else:
            cell.plane = fitPlaneLSQ(free_pts + fixed_pts)

        for v in cell.vertex_ids:
            if v not in fixed_vertices:
                vertices[v].coords = projectToPlane(vertices[v].coords, cell.plane)

    propagateToNeighbors(dependent)
    return validate(RTG)
```

**Важно:** если после пересчёта `isFixed`-вершина оказывается не на плоскости своей ячейки — ошибка `INCONSISTENT_FIXED_VERTEX`, операция откатывается.

### C.6. F-30. Overhang (свес)

**Метод:** offset 2D-контура карниза наружу + пересчёт скатов с фиксацией конька + добавление вертикальных `Overhang`-граней.

```python
def createOverhang(building, offset_m: float):
    wall_footprint = getWallFootprintXY(building)   # shapely.Polygon, FIXED
    eave_footprint = getEaveFootprintXY(building)   # shapely.Polygon
    eave_new = eave_footprint.buffer(offset_m, join_style=2)  # mitre join

    for cell in getRoofCells(building):
        ridge_pts = getFixedRidgePoints(cell)
        eave_pts_new = projectToXY(eave_new.exterior.coords)
        cell.plane = fitPlaneLSQ(ridge_pts + eave_pts_new)

    gap_polygon = eave_new.difference(wall_footprint)
    for ring in polygon_to_rings(gap_polygon):
        new_cell = createVerticalCell(ring, semantic='Overhang')
        new_cell.is_overhang_boundary = True
        cells[new_cell.id] = new_cell

    return validate(RTG)
```

**Критично для налоговой оценки:** `wall_footprint` не меняется → площадь застройки не искажается. `Overhang` маркируется отдельно (`is_overhang_boundary=True`) и при экспорте в CityGML получает тип `WallSurface` с подтипом `Overhang` (по AdV).

### C.7. F-36. Add Dormer (RANSAC + height clustering)

**Метод:** фильтрация точек в выделенной области → RANSAC базовой плоскости → height clustering → DBSCAN → bounding box → snap.

```python
def addDormer(slope_cell, region_polygon_3d, point_cloud):
    pts = filterPointsInPolygon(point_cloud, region_polygon_3d)
    base_plane, inliers = ransacPlane(pts, threshold=tol.planar)
    elevated = pts[[distanceToPlane(p, base_plane) > 0.3 for p in pts]]
    labels = DBSCAN(eps=0.5, min_samples=20).fit(elevated).labels_

    for label in unique(labels):
        cluster_pts = elevated[labels == label]
        bbox = orientedBoundingBox(cluster_pts, align_to=base_plane)
        bbox = snapBaseToPlane(bbox, base_plane)
        dormer = createDormerGeometry(bbox, roof_type='flat')  # или 'gable'
        dormer.semantic_type = 'BuildingInstallation'
        dormer.is_dormer_part = True
        integrateInstallation(RTG, slope_cell, dormer)

    return validate(RTG)
```

**Параметры по умолчанию:** `height_threshold=0.3 м`, `dbscan_eps=0.5 м`, `min_samples=20`. Выносятся в настройки.

### C.8. F-37. Add Chimney

Аналогично C.7, но проще: оператор указывает точку + тип (параллелепипед/цилиндр). Высота определяется по облаку (max Z точек в радиусе 0.5 м над скатом).

```python
def addChimney(slope_cell, click_point, shape='box'):
    pts = filterPointsInRadius(point_cloud, click_point, radius=0.5)
    base_plane = slope_cell.plane
    elevated = pts[[distanceToPlane(p, base_plane) > 0.3 for p in pts]]
    if len(elevated) < 10:
        return error("Недостаточно точек для определения высоты трубы")
    height = max(p.z for p in elevated) - solveZ(base_plane, click_point.x, click_point.y)
    chimney = createChimneyGeometry(click_point, height, shape)
    chimney.semantic_type = 'BuildingInstallation'
    integrateInstallation(RTG, slope_cell, chimney)
    return validate(RTG)
```

def rectangularCut(cell, cut_polygon_2d):

## Приложение D. Протокол Frontend ↔ Backend

**Принцип:** фронтенд — «тонкий клиент» для UI и рендеринга; все геометрические операции — на бэкенде. Это гарантирует единый математический движок и невозможность расхождения реализаций.

### D.1. Транспорт
- **HTTP REST** для загрузки/экспорта и долгих операций (batch).
- **WebSocket** для интерактивного редактирования (низкая задержка).
- **Асинхронная очередь** (Celery/RQ + Redis) для batch-операций (F-62) и тяжёлых валидаций.

### D.2. Формат команды (frontend → backend)

```typescript
interface RTGCommand {
  commandId: string;          // UUID для отслеживания
  buildingId: string;
  operation: 'ALIGN_RIDGE' | 'MOVE_EDGE' | 'RECTANGULAR_CUT' | 'ADD_DORMER' | ...;
  payload: Record<string, unknown>;   // специфичен для операции
  expectedVersion: number;    // для optimistic locking
}
```

Пример для F-19:
```json
{
  "commandId": "uuid",
  "buildingId": "bldg-42",
  "operation": "ALIGN_RIDGE",
  "payload": {
    "edgeId": "edge-7",
    "newLine": { "p1": [x1,y1,z1], "p2": [x2,y2,z2] }
  },
  "expectedVersion": 17
}
```

### D.3. Формат ответа (backend → frontend)

```typescript
interface RTGCommandResult {
  commandId: string;
  success: boolean;
  newVersion: number;
  diff: {
    verticesAdded: RTGVertex[];
    verticesUpdated: RTGVertex[];
    verticesRemoved: string[];
    edgesAdded: RTGEdge[];
    edgesUpdated: RTGEdge[];
    edgesRemoved: string[];
    cellsAdded: RTGCell[];
    cellsUpdated: RTGCell[];
    cellsRemoved: string[];
  };
  validation: ValidationReport;
  warnings: string[];   // напр., "Ridge direction changed"
}
```

**Ключевое решение:** бэкенд возвращает **дифф**, а не полный RTG. Фронтенд применяет дифф к локальному состоянию (`zustand`), что минимизирует трафик.

### D.4. Обработка ошибок

- `success: false` + `validation.isValid: false` → фронтенд **откатывает** оптимистичное обновление и показывает ошибки оператору.
- `409 Conflict` (version mismatch) → фронтенд запрашивает актуальный RTG и переприменяет команду.
- Все команды **идемпотентны** по `commandId` (повторная отправка не создаёт дубль).

### D.5. Где что считается

| Операция | Где | Почему |
|---|---|---|
| Импорт, парсинг LAS/CityGML | Backend | Тяжело, требует GDAL |
| Построение RTG (F-16) | Backend | RANSAC, кластеризация |
| Рендеринг облака | Frontend (Potree) | Интерактивность |
| Перемещение мыши / привязка | Frontend (Three.js raycast) | Задержка <16 мс |
| Все операции редактирования (F-19..F-38) | Backend | Единый математический движок |
| Валидация (F-55) | Backend (val3dity) | Бинарник + ISO 19107 |
| Расчёт метрик (F-53) | Backend | Точность, аудит |
| Экспорт | Backend | Форматы, валидация перед выгрузкой |

**Оптимизация:** для операций, требующих мгновенной обратной связи (F-23 Orthogonal Snapping, F-25 перетаскивание), фронтенд показывает **предварительный результат** локально (простое проецирование), а финальную геометрию получает от бэкенда после `mouseup`. Если бэкенд вернул другой результат — плавная коррекция.

## Приложение F. Unit-тестовые инварианты

Каждая операция редактирования должна проходить следующие проверки (реализуются как property-based tests через `hypothesis` в Python или `fast-check` в TS):

1. **c(e) = 2:** для каждого ребра после операции `len(edge.faces) == 2`.
2. **Планарность:** для каждой ячейки все вершины лежат в `cell.plane` с допуском `tol.planar`.
3. **Нормировка нормали:** `a²+b²+c² == 1 ± 1e-9`.
4. **Согласованность ориентации:** для любого ребра нормали двух граней направлены в противоположные стороны (внешняя ориентация).
5. **Сохранение объёма (для move/extend):** изменение объёма после операции соответствует ожидаемому (для F-30 — объём по footprint стен **не меняется**).
6. **Идемпотентность:** повторное применение той же команды с тем же `commandId` не меняет RTG.
7. **Обратимость:** для операций F-19..F-25 существует обратная операция, возвращающая исходный RTG с точностью до `1e-6`.

**Пример property-based теста (Python):**

```python
@given(rtg=rtg_strategy(), new_line=line_strategy())
def test_align_ridge_preserves_manifold(rtg, new_line):
    edge = pick_random_ridge(rtg)
    result = align_ridge(rtg, edge, new_line)
    assert result.validation.isValid
    for e in result.rtg.edges.values():
        assert len(e.faces) == 2
    for c in result.rtg.cells.values():
        assert all(distanceToPlane(v, c.plane) < c.tolerance for v in c.vertices)
```
